# 变更：add-extensions

## Why

《学期项目说明》把「技能上传」与「关怀式对话」列为拓展项（「拓展未完成不影响核心主路径验收」）。核心主路径已全部完成，本次补齐这两项，让系统具备「教师可导入第三方技能包」与「面向情绪状态的差异化回应」两项产品化能力。

「高可用」按 AGENTS.md 不做清单明确排除，不在本次范围。

## What Changes

### 拓展一：技能上传

- 新增 `POST /api/skills/import`（教师专用，multipart `file`）。
- 支持 `.md`（单段 source 文本）与 `.json`（`{source}` 或扁平 `{name, description, trigger, tools, subject}`）两种格式；上限 64KB。
- 白名单外扩展名 415、超限 413、非 UTF-8 400、解析失败 400、同名技能 409、工具引用四查不通过 400。
- 导入的技能一律 `enabled=0`，source 被规整为单段文本（`启用：否`），教师可在列表中预览、编辑、启用。
- 教师仪表盘技能区新增文件选择与「导入技能」按钮。
- 审计 `action=create, target_type=skill`，`detail` 含 `import=true` 与原始文件名。

### 拓展二：关怀式对话

- seed 新增内置技能「关怀式对话」，与解题引导、错题讲解并列绑定默认助手，`enabled=1`。
- chat 管线新增确定性注入门：仅当学生消息命中挫败/焦虑词表（不会/听不懂/好难/崩溃/放弃/压力/焦虑等）时才注入该技能，普通提问不注入，避免话术污染与 prompt 膨胀。
- 命中关怀时，即使检索零命中也不走「资料中未找到」固定文案，而是调用模型做共情回应（此时安抚优先于机械正确）。
- 技能被教师停用后，关怀注入立即失效。

## Non-Goals

- 不做情感识别的模型调用（不做额外网关开销），只用本地词表判定。
- 不做技能包签名校验、依赖安装、工具脚本执行（技能只含提示词，不含可执行代码）。
- 不做轻量端 H5、高可用（前者需浏览器回归，后者在不做清单内）。
- 不做技能市场的导入导出与分享。

## Capabilities

- `skill-import`（新增）：技能包上传的格式、校验、落库状态与审计。
- `assistant-skills`（修改）：新增「关怀式对话」技能及其条件注入规则。
- `api-docs`（修改）：新增 `/api/skills/import` 的 OpenAPI 描述。
