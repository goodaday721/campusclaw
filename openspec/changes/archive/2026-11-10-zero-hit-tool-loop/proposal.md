# 变更：zero-hit-tool-loop

## Why

学生用解题助手问纯工具型问题（如「10千克等于多少克」）时，知识库检索零命中，第 5 课的短路逻辑直接返回固定话术「资料中未找到相关内容」，根本走不到第 6 课的 MCP 工具循环——技能里的 `unit_convert@campus-tools` 引用形同虚设。工具调用的入口被「检索是否命中」劫持，与 tool-calls 能力「让技能中的工具引用在会话中真正可执行」的目标冲突：只有问题文本恰好命中资料时工具才可能被调用。

## What Changes

- 调整 `app/services/chat.py::start` 的零命中短路条件：零命中但本轮智能体绑定的启用技能引用了 MCP 工具时不再短路，照常构建消息与候选集并运行工具循环。
- 工具循环结束后按既有「任一调用 ok」判据分流：有 ok 数据 → 系统提示追加 TOOL_DATA_NOTE 并调模型流式回答（citations 为空、meta.tool_calls 携带调用记录）；全部 denied/error/无成功数据 → 维持现状，回答固定话术且不调模型。
- `sse_stream` 的固定话术分支改按 `gen is None` 判定（原按 `no_match` 判定），保证零命中+工具成功时走流式回答路径。
- 修复 `mcp-server/tools.py::unit_convert` 的参数容错：inputSchema 描述的示例格式（`如 千米/km`）会诱导真实模型传「中文/英文」复合单位，原实现只认裸单位导致每次调用都返回「换算失败」文本（isError=false，审计记 ok）——现接受斜杠任一侧匹配（实测审计行证实）。
- `/ask` 检索问答链路不改：零命中仍固定话术不调模型。
- `tests/test_mcp.py::TestToolLoop` 新增 3 条用例：零命中+工具成功→流式回答、零命中+工具出错→固定话术、零命中+服务器已断开→固定话术；`TestMcpServerProtocol` 新增复合单位格式用例；现有零命中用例（朴素智能体、材料过滤）语义不变。
- 同步 `docs/standards/ai.md` 与 `README.md` 中「零命中不调模型」的解题助手例外措辞。

## Non-Goals

- 不改 `/ask` 链路，不改固定话术文案本身。
- 不做技能与问题的语义匹配（是否可调工具仍由当轮技能引用决定，不智能判断）。
- 不改工具循环的轮次/次数上限、注入防护与审计语义。
- 不给零命中+工具成功的回答伪造 citations。

## Capabilities

- `assistant-chat`（修改）：零命中回答要求增加「技能引用 MCP 工具时先跑工具循环、有 ok 数据才调模型」的例外。
- `tool-calls`（修改）：工具调用循环明确在零命中时也执行，工具成功返回的数据可独立作为回答依据。
