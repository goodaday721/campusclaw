## Why

系统当前没有任何身份与数据边界能力：访问受保护页面无需登录、角色无区分、班级之间数据互相可见。校园教学场景要求教师能向本班知识库投放材料且不被越权访问，学生只能查看本班内容、不能上传。本次变更建立认证、角色权限、班级数据隔离与知识库材料管理的最小可用闭环，并补齐运行时契约（健康检查、容器化启动、密钥来源约束），为后续教学功能提供安全底座。

## What Changes

- 新增账号密码登录：教师、学生均使用账号密码登录；会话基于服务端签发的 JWT，密钥仅来自服务端环境变量。
- 新增未登录拦截：访问受保护页面/接口且未登录时，引导跳转登录页（HTTP 401 + 登录页重定向）。
- 新增密码哈希存储：密码必须以单向哈希（bcrypt/argon2）存储，禁止明文落库或落日志。
- 新增角色权限：区分 `teacher` 与 `student`；学生调用材料上传接口必须被服务端拒绝（403）。
- 新增班级数据隔离：班级是数据边界，A 班用户访问 B 班材料必须被服务端拒绝；过滤必须在服务端查询层强制，不依赖前端隐藏按钮。
- 新增知识库材料管理：教师上传材料后写入知识库，本班材料列表可查到该记录；学生可读取本班材料列表。
- 新增运行时契约：应用通过 Docker Compose 启动；提供 `GET /health` 返回服务存活状态；密钥与连接串只放服务端环境变量。
- 新增预置演示数据：首次启动通过种子脚本预置至少两个班级与分属两班的教师/学生账号，密码哈希存储，重复启动不重复预置。

## Non-Goals

本变更（本课范围）明确不做以下事项：

- 不实现知识库检索与问答：不做全文检索、语义搜索或基于材料内容的问答系统。
- 不实现对话助手：不做 AI 对话、助教机器人或自然语言交互功能。
- 不实现作业提交与批改：不做作业流程、学生提交、教师批改与评分。
- 不实现 SSO 与生产高可用：不做单点登录、第三方 OAuth 接入、多副本负载均衡与生产级 HA 部署。
- 不实现注册/找回密码自助流程（初始账号由迁移/种子脚本预置）。
- 不实现细粒度资源级权限（如单条材料的分享、协作者）。

## Capabilities

### New Capabilities

- `user-auth`: 账号密码登录、JWT 会话、未登录拦截跳转登录页、密码哈希存储约束、密钥来源约束。
- `role-access`: 教师与学生角色区分；学生调用上传接口被服务端拒绝。
- `class-isolation`: 班级作为数据边界；服务端查询层强制过滤；跨班访问被拒绝。
- `knowledge-materials`: 教师上传材料写入知识库；本班材料列表查询；与班级隔离协同。
- `app-runtime`: Docker Compose 启动；`GET /health` 健康检查；密钥/连接串仅来自服务端环境变量；首次启动预置演示数据（班级/教师/学生，密码哈希，幂等不重复）。

### Modified Capabilities

无（项目无既有 spec，全部为新建）。

## Impact

- 受影响代码：新增 Flask 后端、SQLite 数据库；新增用户表、班级表、知识库材料表及其迁移；新增认证装饰器、角色鉴权装饰器、班级作用域过滤逻辑；新增登录、上传、材料列表、健康检查路由。
- 受影响 API：新增 `POST /auth/login`、`GET /auth/me`、`POST /materials`、`GET /materials`、`GET /health` 等。
- 依赖：bcrypt/argon2、PyJWT、sqlite3/SQLAlchemy、Werkzeug（文件上传）、Docker Compose。
- 安全影响：密码哈希存储、JWT 密钥仅来自环境变量、班级隔离在服务端强制，是本变更的硬性安全约束。
